# Develop the Claude Code harness (claude-sandbox)

Repository-only skill (not distributed). Harness **policy criteria** live in the `review-claude-config` skill; this skill covers the **generator's requirements and how to change it**. Do not duplicate policy here.

## Purpose and scope

The repository serves three use cases (see README):

1. Disposable dev container for one-shot runs.
2. Workbench for the operator's other repositories.
3. Developing, verifying and distributing the Claude Code harness.

- **Managed here: the harness only** — `.claude/settings.json`, `.claude/hooks/guard.sh`, skills, agents, `CLAUDE.md`, `AGENTS.md`.
- **Not managed by the generator: `.devcontainer/`** (originally generated by codespacegen; hand-maintained here). The harness treats the container as a premise only.
- Keep the root a clean runtime: generator sources live only under `harness/`; generated output is never committed to `master`.

## Structure

| Path | Role |
|---|---|
| `harness/config.json` | The only customization input (`gh_read`, `curl`, `attribution`, `skills`, `agents`, `root.skills`, `root.agents`) |
| `harness/lang.json` | Package managers per language: `lockfiles`, `install` (lockfile installs → ask), `add` (→ block) |
| `harness/templates/` | `settings.base.json`, `guard.sh` (placeholders `@@LOCK_RULES@@` / `@@PKG_VERBS@@` / `@@PKG_BARE@@`), skills, agents, `CLAUDE.md`, `AGENTS.md` |
| `harness/tests/cases/` | `baseline.tsv` (safety baseline), `common.tsv`, `<option>-<value>.tsv`; package cases are generated from `lang.json` |
| `harness/scripts/generate.sh` | Builds `sample_harness/<variant>/` (`base` + each language) and `harness/build/root/`, tests every set; `--check-root` compares the root |
| `harness/scripts/setup_harness.sh` | Installs a variant from the `dist` branch into another repository |
| `.github/workflows/harness.yml` | On `master` push / manual run: generate + test + `--check-root`, then force-push `sample_harness/` to `dist` |

## Design decisions (do not revisit without the user)

- Customization comes **only** from committed `config.json` / `lang.json`. No workflow inputs, no interactive options in `setup_harness.sh` (input outside the workflow is noise).
- Distribution: orphan `dist` branch, force-pushed, containing only `sample_harness/<variant>/`, mirroring `taka1156/codespace-template`.
- Variants: `base` (no language, every package install blocked) + one per `lang.json` key. **No "all" variant.**
- Languages: node, python, go, rust. **Ruby and PHP are out of scope**; do not add them or Ruby/PHP-specific rules.
- The root uses `base` + `config.root` extras (`develop-harness` skill, `sync-readme` agent). These extras are not distributed.
- Root `CLAUDE.md` / `AGENTS.md` are templates and are distributed; never put repository-specific content in them (put it here instead).
- Default options: `gh_read` = allow, `curl` = ask, `attribution` = false.

## Requirements

- The safety baseline (see `review-claude-config`) holds for every variant and config; it cannot be made optional.
- UNDER (looser than policy) or a baseline failure fails the build; OVER (stops work more than policy) is a warning.
- The root must equal `harness/build/root/` (`--check-root`), otherwise CI fails.
- When the policy table in `review-claude-config/SKILL.md` changes, update `harness/tests/cases/` in the same change, and vice versa.
- Every new hook rule gets test cases (a positive case and, where a look-alike exists, a false-positive case).
- Scripts must run on GitHub's `ubuntu-latest` and in the dev container (bash, jq, GNU sed/grep).

## Change procedure

1. Edit `harness/templates/`, `harness/tests/cases/`, `harness/config.json` or `harness/lang.json`. **Never edit generated files** (`sample_harness/`, `harness/build/`, the root `.claude/`).
2. Run `bash harness/scripts/generate.sh` and fix until every variant reports `baseline_fail=0` and `UNDER=0`.
3. Root update (`.claude/` is read-only in the container and guarded): ask the user to run on the host
   `cp -R harness/build/root/. .`, delete files no longer generated, then confirm `bash harness/scripts/generate.sh --check-root`.
4. Update README.md and README.ja.md when behavior, structure or usage changes (`sync-readme` agent rules).
5. Commit directly on `master` in logical units, without Claude co-author lines. Push only after `--check-root` passes.

## Working notes

- Bash commands that mention `.claude/settings.json`, `.claude/hooks` or `.git/hooks` are blocked by the guard, even for generated copies under `sample_harness/` or `harness/build/`. Use the Read tool, `cd` into the directory, or write commands into a script file.
- Commit messages that mention guarded paths or commands may be blocked; write them to a file and use `git commit -F`.
